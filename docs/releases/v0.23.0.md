# Downshift v0.23.0

Release date: 2026-11-25.

This release closes the compaction and telemetry gaps identified after v0.22.0: postrun compaction now shows up in `discover`, Sentry and Datadog MCP payloads are semantically pruned from ~2 KB, repeated MCP doc reads in the same session deduplicate to short CCR pointers, `downshift retrieve` outputs are never re-compacted, `providers` responses are slimmed by default, and `report` / `stats` / `doctor` / `events` share consistent windows and fields.

## Highlights

- **Discover counts postrun compaction (`#223`)**: `downshift discover` now reads postrun compaction markers (`[downshift compact: X to Y bytes]`) and `exec-events` separately for bash and MCP tools instead of reporting `0.0%` non-bash coverage.
- **Canonical `downshift compact` docs (`#221`)**: standardized `skills/downshift-orchestrator/SKILL.md` and 13 documentation files on `downshift compact` (keeping `compactor` as an alias).
- **Sentry & Datadog MCP payload pruners (`#226`)**: semantic pruners for `mcp__sentry__search_issues`, `mcp__sentry__search_events`, and `mcp__datadog__execute_code` strip noisy metadata from ~2 KB onward; fixture benchmarks cut average payload from `4,682 -> 2,497` bytes (`-46.7%`).
- **Idempotent MCP doc dedup (`#230`)**: repeated identical idempotent MCP doc/skill reads (`load_datadog_skill`, `list_datadog_skills`, etc.) in the same session emit a short CCR pointer instead of repeating the full body.
- **Slimmer `providers` MCP payload (`#222`)**: omits static `agent_default_tiers` by default (`include_agent_tiers: true` opts in), cutting the default response from `1,089 -> 176` bytes (`-83.8%`).
- **Never re-compact `downshift retrieve` (`#224`)**: both CLI `downshift retrieve` and MCP `retrieve` results are exempted from postrun re-compaction (`PassthroughRetrieve`), eliminating retrieve loops.
- **Sensor & telemetry accuracy (`#225`, `#229`)**: `context-compactions.jsonl` records real `applied` and `reduced_bytes` with log rotation; `exec-retrievals.jsonl` stores tool/family metadata and matches the report window; `childend` propagates `effort`, `complexity`, and `verification` into `events.jsonl`.
- **Unified `report` / `stats` / `discover` & `doctor` (`#227`, `#228`)**: `report` and `stats` read the same compaction source and window, compound shell commands (`cd X && cmd`, `for ...`, functions) classify their inner family instead of `unknown`, and `doctor` collapses inactive harness warnings (>30d) while flagging stale `scores.json` (>7d).
